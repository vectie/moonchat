# Edit structured artifacts from review discussion

Use `review_json_edit` to turn an objection into explicit typed changes in a
retained JSON configuration, plan or export. Choose existing fields or array
elements with canonical JSON Pointers, supply their expected values, preview
the candidate, and retain its linked pending review. You can change a boolean,
number, null, string, object or array without rewriting JSON as line fragments.

This extends the [JSON evidence intake](REVIEW_JSON_IMPORT.md) and
[review-linked text editing](REVIEW_TEXT_EDITS.md) journeys. It is source
authoring, not an approval, provider connection or application configuration
write. No edited concern is automatically resolved.

## Try the pilot configuration

Use a trusted native build of `cmd/review_json_edit`:

```sh
EDIT=/absolute/path/to/review_json_edit.exe
"$EDIT" catalog examples/review-json-edits/source.json
"$EDIT" draft examples/review-json-edits/review.json examples/review-json-edits/source.json > /new/path/blank-plan.json
"$EDIT" preview examples/review-json-edits/selected-edits.json examples/review-json-edits/review.json examples/review-json-edits/source.json examples/review-json-edits/review.json
"$EDIT" source examples/review-json-edits/selected-edits.json examples/review-json-edits/review.json examples/review-json-edits/source.json examples/review-json-edits/review.json > /new/path/candidate-source.json
"$EDIT" bundle examples/review-json-edits/selected-edits.json examples/review-json-edits/review.json examples/review-json-edits/source.json examples/review-json-edits/review.json > /new/path/candidate-review.json
```

The [synthetic sample](../examples/review-json-edits/README.md) disables launch,
limits the pilot, names a rollback owner and revises the region list. It includes
actual generated source, review and preview outputs. All original discussion
entries and named questions remain in the new bundle. Retain both generations.

## Plan the edits

The blank `moonchat.review-json-edits.v1` plan binds exact original bundle and
source bytes. Supply a new `next_source_artifact_ref`, a new
`next_source_revision_id`, an explicit `recorded_at`, and 1..100 edits. Each edit
has a unique safe `key`, an existing `entry_id`, a canonical `pointer`, an
`expected_value`, and a typed `replacement`. See the sample for a complete plan.

The empty pointer selects the entire root, `/regions/0` selects the first array
element, `/` selects an empty object key, and `~0`/`~1` escape tilde/slash in
names. Copy pointers from the catalog. Missing fields, `-`, leading-zero array
indices, JSONPath and fragment syntax are refused. Replace an entire selected
array/object to insert, remove or reorder members explicitly. There is no
implicit path creation, append, merge, arithmetic, fuzzy selection or patch
execution language.

Every selection refers to the original artifact. Duplicate or overlapping
parent/child selections reject the whole plan. Disjoint edits are order
independent. Expected values compare decoded serialization, including object
member order and exact numeric token spelling: `50`, `50.0` and `5e1` are distinct
expected values. An equivalent object written in a different member order may
fail the expected-value check; deliberately reordering its replacement counts
as a source change. Copy complete selected objects in catalog/source order.
Copy exact numeric values from this catalog or the original source. No-op
replacements are refused. Strings remain strings; numbers remain numbers;
null never means deletion.

Unselected data is retained semantically, including large integers and precise
decimal token spellings. Output formatting is canonical pretty JSON with one
trailing newline. Whitespace, object order and string escape spellings may
change. The candidate bundle's digest binds those exact generated bytes.
Original source and review bytes are never overwritten by the commands.

## Continue and recover

Every mode validates the whole edit set before emitting candidate output.
Errors use stderr and a nonzero exit, with empty stdout. Changed source or
bundle bytes, stale expected values, unknown entries and invalid late edits
require a fresh plan or correction; they never partially apply a change.

Commands write stdout only. Redirect to new paths, never inputs; shell
redirection occurs before validation and may leave an empty file on failure.
The candidate reference is portable metadata, not a file-save destination.
Store generated source bytes at that reference when organizing your workspace,
retain the plan and predecessor, and reopen the candidate using existing
`review_export`, `review_packet`, or `review_decide prepare` consumers.

Previous approve/reject/defer receipts remain historical and are not copied.
The new review is pending with the same host conversation identities,
participants, entries and required decisions. Another source edit starts from
that candidate's retained bundle/source. The host still owns human identity,
durable storage, receipt delivery and independent receiving-product acceptance.

## Bounds and evidence

Sources and final candidates allow 1 MiB UTF-8, depth 64 and 10,000 JSON nodes.
Plans allow 8 MiB UTF-8 and parsing depth 64, and selected replacements obey
the source limits. Duplicate decoded object keys and malformed UTF-8/JSON are
refused before selection. This in-memory authoring API is not a streaming or
binary document editor. The CLI reads local files before library size checks.

Pure APIs: `prepare_review_json_edits`, `parse_review_json_edits`,
`apply_review_json_edits`, `preview_review_json_edits`. Application returns the
existing `ReviewTextEditResult` containing candidate text and an ordinary v1
review bundle. Source JSON cataloging shares the exact-number reader so the
values shown for selection cannot silently round.

Focused production-library tests and the native CLI script exercise typed edits,
exact numeric preservation, stale/conflicting selections, unchanged inputs and
consumption by the existing decision-form and Markdown commands. They do not
qualify a live host screen, authentication, receipt return, browser accessibility,
ordinary-user L2 readiness or complete authored release gates.
